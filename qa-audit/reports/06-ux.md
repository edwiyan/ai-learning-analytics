## New Defects Found

### DEF-21 — P1: Vite proxy conflict breaks page refresh on 3 frontend routes
**Area:** `frontend/vite.config.js`  
**Evidence:** Direct navigation or page refresh on `/users`, `/analytics`, `/resources` returns raw backend JSON instead of the React app. The Vite proxy forwards these paths to the backend before React Router can handle them.  
**Impact:** Any panel member who refreshes the browser tab while on the Users page or Analytics page will see `{"detail":"Not authenticated"}` (unauthenticated) or API JSON data (if somehow authenticated at the backend). Core pages are broken on reload.  
**Fix:** Remove the exact matches from Vite proxy and only proxy sub-paths:
```js
// vite.config.js — change exact paths to sub-path prefixes only used for API
// Option A: Remove /users and /analytics from proxy (API calls already go through /auth, etc.)
// Option B: Rename frontend routes — e.g., /users → /user-management
// Option C: Add changeOrigin + rewrite to only proxy requests with specific headers
```
Simplest fix: rename the conflicting frontend routes:
- `/users` → `/user-management`
- `/analytics` → `/analytics-page`  
- `/resources` → `/resource-library`

---

### DEF-22 — P2: Role display names show internal identifiers with underscores
**Area:** `frontend/src/components/Layout.jsx` (sidebar role label)  
**Evidence:** The sidebar shows the raw role string from the JWT:
- `Program_director` (should read "Program Director")
- `Vp_academic_affairs` (should read "VP for Academic Affairs")
- `Admin`, `Instructor`, `Student` are correctly capitalized  
**Impact:** Panel members will see the internal role identifiers, which appear unprofessional.  
**Fix:** Map role strings to display names:
```js
const ROLE_LABELS = {
  admin: 'Admin',
  instructor: 'Instructor',
  student: 'Student',
  program_director: 'Program Director',
  dean: 'Dean',
  vp_academic_affairs: 'VP for Academic Affairs',
};
```

---

### DEF-23 — P3: Enrollment table shows "STUDENT ID HASH" as column header
**Area:** `frontend/src/pages/EnrollmentPage.jsx` (enrollment roster table)  
**Evidence:** The column header reads "STUDENT ID HASH" — exposing the SHA-256 hashing implementation detail to admin users. The displayed values appear to be plain student IDs, making the label additionally misleading.  
**Fix:** Rename column header to "Student ID".

---

### DEF-24 — P2: Student dashboard defaults to empty state — no data visible until interaction
**Area:** `frontend/src/pages/StudentDashboard.jsx`  
**Evidence:** After login, the student sees only "Select a course above to view your analytics" with a placeholder icon. The user must manually select a course from the dropdown before any dashboard content appears.  
**Impact:** For the defense demo, the student dashboard appears empty when first shown. A panel member who looks at the screen before the proctor interacts will see no data.  
**Fix:** Auto-select the first enrolled course on mount:
```jsx
useEffect(() => {
  if (courses?.length > 0 && !selectedCourse) {
    setSelectedCourse(courses[0]);
  }
}, [courses]);
```
